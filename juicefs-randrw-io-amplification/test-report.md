# 随机读写对象IO放大测试记录

[English](test-report.en.md)

测试使用JuiceFS v1.4.1（`0b90c7db5a929ae6adc5faad948d108efd2c99f9`）、TiKV和Ceph RADOS，fio版本为3.28。卷BlockSize和最大FUSE IO均为256 KiB，关闭本地数据缓存和writeback。完整挂载参数、fio参数及采集方法见[测试方法](reproduce/README.md)。

对象读／写放大分别按同一客户端、同一时间窗的GET／PUT字节除以应用读／写字节计算。应用字节由JuiceFS记录的FUSE IO统计数据与fio输出核对；对象字节包含JuiceFS合并IO，尚未计入Ceph内部EC及磁盘开销。初始化、人工合并和CRC校验在正式统计窗口之外。

## 1. 随机读写：约23.7倍对象IO放大

创建128个256 MiB文件，共32 GiB。顺序初始化后，逐文件单线程compact，确认每个64 MiB chunk只有一条完整slice映射；完成初始CRC，正常卸载并重新挂载，再开始30分钟测试。

fio使用 `randrw`、50%读／50%写、`bs=256K`、`direct=1`、`libaio`、`iodepth=128`，128个job各访问一个文件。每job设置 `rate=64k,64k`，应用读、写合计各约8 MiB/s。正式期间不做人工合并或CRC。

| 统计项 | 30分钟测试结果 |
|---|---:|
| 应用读取／写入 | 各14.0625 GiB |
| 对象GET／PUT | 333.00317／332.8125 GiB |
| 对象读／写放大 | **23.68023／23.66667倍** |
| 合并计数／累计规模 | 5100次／318.75 GiB |
| 平均每次合并规模 | 64 MiB |
| fio／对象请求错误 | 0 |
| 最终完整CRC | 32 GiB通过 |

对象PUT满足 `14.0625 GiB应用写入 + 318.75 GiB合并规模 = 332.8125 GiB`，约95.77%的对象写入可由合并规模解释。GET比“应用读取＋合并规模”多195.25 MiB，约占GET的0.0573%，这部分来源尚未细分。

正式结束后，为整理文件历史而人工执行的合并另产生GET／PUT各29.75 GiB，未计入上表；最终CRC也单独统计。[该实验的原始记录](raw-test-data/upstream-independent/)。

## 2. 单文件最小复现：两次小覆盖后读取触发64 MiB合并

分别创建两个64 MiB文件，均使用 `bs=4M`、`psync/QD1`、`direct=1` 初始化，确认各自只有一条完整64 MiB slice映射。完成初始CRC后，执行以下对照，每次覆盖写结束均fsync：

- 单处覆盖：在偏移16 MiB处写256 KiB。
- 两处覆盖：在偏移16 MiB和48 MiB处各写256 KiB，共512 KiB。

覆盖后记录映射，再正常卸载并以新进程挂载，使首次读取不命中旧进程的映射缓存。两种情况均只读取偏移0的256 KiB，等待该次读取及后台对象请求结束后记录结果，最后才进行完整CRC。

| 统计项 | 单处覆盖 | 两处覆盖 |
|---|---:|---:|
| 应用覆盖写入 | 256 KiB | 512 KiB |
| 覆盖阶段对象GET／PUT | 0／256 KiB | 0／512 KiB |
| 覆盖后原始映射数／有效片段数 | 2／3 | 3／5 |
| 随后应用读取 | 256 KiB | 256 KiB |
| 该次读取及后台工作产生的GET | 256 KiB | **64.5 MiB** |
| 该次读取及后台工作产生的PUT | 0 | **64 MiB** |
| 合并次数／规模 | 0／0 | **1／64 MiB** |
| 读取及后台工作结束后的原始映射数 | 2 | 1 |
| fio／对象请求错误 | 0 | 0 |
| 最终完整CRC | 64 MiB通过 | 64 MiB通过 |

初始数据记为A。一次覆盖B后，保存A、B两条映射，有效内容为“A前段、B、A后段”，共3段；再覆盖C后，保存A、B、C三条映射，有效内容为“A前段、B、A中段、C、A尾段”，共5段，达到读侧请求合并的条件。

两处覆盖的GET为64.5 MiB，其中64 MiB对应合并范围，256 KiB为应用读取量，另外256 KiB尚未细分。合并后映射变为一个新slice，说明少量覆盖后的读取可以触发整个64 MiB范围的重新上传。[单处覆盖原始记录](raw-test-data/mini-negative/)／[两处覆盖原始记录](raw-test-data/mini-positive/)。

上述数据均可通过[原始记录](raw-test-data/README.md)和[复算程序](tools/recompute.py)核对；[results.json](results.json)为据此计算的汇总。
