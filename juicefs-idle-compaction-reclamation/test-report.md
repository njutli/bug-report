2026-09-27。区分原生回收观察、人工维护和候选自动合并，不将三者混为长稳通过。

## 1. 原问题与机制观测

| 试验 | 数据与结果 | 边界 |
| --- | --- | --- |
| 原 LT-002 | 128 GiB 固定数据集，2 小时 256K randrw；fio、完整 CRC 通过 | 没有逐次 compact 分支日志 |
| 空闲观察 | 289 次采样、约 24 小时全部 HEALTH_OK；pool stored 从 348,283,477,420 降至 348,129,107,372 B，仅减少 0.144 GiB；仍高于写前基线 89.795 GiB；compact count 始终 2255 | 有限观察，不证明“永远不会回收”；不能逐条归因 |
| B2 新文件观测 | 1 GiB / 8 GiB 覆盖，26,649 触发、26,616 跳过、33 次执行成功；空闲约 3 分钟仍 9,837 记录 | 私有客户端 no-bgjob；发生率不能外推 |

以上 retained slice 量是文件原始引用口径，不直接等同 EC 后物理盘字节，也不证明 BlueStore DB 物理空间释放。

## 4. C2：独占子树 TiKV/Ceph canary

**通过：14:57 正常卸载结束；不是生产长稳验收。** 独立复算原始 metadata dump、4 份 fio JSON、执行命令账和 72 个健康样本。

| 采样阶段 | 记录数 | 全 slice 字节 |
| --- | ---: | ---: |
| 写后立即，扫描关闭 | 7,320 | 3,025,666,048 |
| 停写 180 秒后 | 3,402 | 1,981,022,208 |
| 再隔 30 秒、卸载后、开启前复查 | 3,402 | 1,981,022,208 |
| 新会话开启扫描后 2.4 秒 | 3,402 | 1,981,022,208 |
| 34.5 秒 | 2,696 | 1,794,899,968 |
| 66.7 秒 | 854 | 1,303,117,824 |
| 98.7 秒 | 16 | 1,073,741,824 |

OFF 稳定点至 ON 起点的 chunk 数组逐项相同，不能把 7,320→3,402 的旧异步合并算入候选效果。扫描 root 与新子树 inode 一致；首轮遍历 55.783 秒。98.7 秒是确认已收敛的采样点，不是精确完成时刻或生产回收期限。引用收敛之后 34 秒才开始最终完整 1 GiB CRC，error=0；文件 inode/大小/mtime 不变。

引用净减 **907,280,384 B（865.25 MiB）**；pool stored 净减 **907,673,600 B（865.625 MiB）**、3,462 对象。池终点较布局基线低 0.375 MiB、对象数相同；不把该小差额当作本文件精确收益。72 个健康样本均 HEALTH_OK、6 OSD up/in，最小 max_avail=863,464,259,584 B。命令账确认只有 **2 次私有 mount、2 次正常 unmount、0 次手工 compact/GC**；重复 UMOUNT_PASS 事件是接续时重新确认，不是重复执行卸载。

同一候选关闭新扫描（interval=0）创建 1GiB CRC 文件；16 个 job 各覆盖独立 64MiB 范围，每 job 固定写 512MiB，总写 8GiB，bs256K/QD4、各限速 1MiB/s。先用缩小文件在本地验证多 job 分区和完整 CRC 的语义。

写后不读文件、不手工 compact，只做定向 metadata dump：空闲 180 秒，继续确认两份间隔 30 秒的快照相同。正常卸载，再用 interval=15s 重挂同一子树；没有新用户 IO，只观察定时扫描。只有引用收敛后才做完整 CRC，再正常卸载。这样不会将 CRC 读触发的合并算作后台修复。

两次挂载的 UUID、子目录、生效参数、worker/PID 启动时间和二进制路径均验证；原挂载不变。由于 daemon 截断长进程标题，首次挂载后的 argv 完整匹配门误停，尚未写数据；改为只读生效配置+exe+进程拓扑校验后接续原挂载，不重复首次 mount。记录保留，不隐藏为“首次无故障”。

OFF 正常卸载后又遇到执行器竞态：ps 枚举的父进程在读取 `/proc/<pid>/exe` 前退出，读取失败导致误停。独立确认私有挂载/进程已消失、文件身份与保存的冷态 metadata 一致后，只接续 ON 阶段；处理已退出/僵尸进程的只读识别，不重复写入或 OFF 挂载。接续时又发现内存 histogram 整数键与 JSON 字符串键造成假差异；独立比较落盘快照确实相同，改为完整 JSON 规范化比较并补正/负例测试后才继续。三次执行器问题均保留原始失败记录；候选代码及二进制未改，ON 挂载未因此重复。

`--subdir` 约束新增扫描，但普通后台清理仍可参与全卷已符合删除条件的对象清理。因此**目标引用收敛与内容校验是主证据，全池 stored 是辅助证据**。
